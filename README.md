# Персональний помічник

Консольний застосунок для керування **контактами** та **нотатками з тегами**.
Дані зберігаються на диску в папці користувача й не зникають після перезапуску.

Можливості:

- контакти з іменем, адресою, кількома телефонами, email і днем народження;
- перевірка телефону та email під час додавання й редагування (поле питається повторно);
- пошук контактів за ім'ям, телефоном, email, адресою чи датою народження;
- список контактів, у яких день народження в найближчі N днів;
- нотатки з тегами: пошук, редагування, видалення;
- пошук нотаток за тегами та групування (сортування) нотаток за тегами;
- автодоповнення команд клавішею Tab і підказка «можливо, ви мали на увазі…».

## Встановлення

Потрібен Python 3.10 або новіший.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

## Запуск

```bash
assistant
```

Після запуску введіть команду. Помічник запитає потрібні дані крок за кроком.
`Ctrl+C` посеред введення скасовує поточну команду; `Ctrl+C` або `Ctrl+D` на запрошенні `>>>` завершує роботу.

| Команда | Дія |
|---|---|
| `help` | Список команд |
| `exit`, `close` | Вихід |
| `add-contact` | Додати контакт: ім'я → телефони (через кому) → email → адреса → день народження |
| `list-contacts` | Усі контакти |
| `search-contacts` | Пошук контактів |
| `edit-contact` | Редагування: Enter — залишити значення, `-` — очистити поле |
| `delete-contact` | Видалити контакт (з підтвердженням) |
| `birthdays` | Дні народження в найближчі N днів (0–365) |
| `add-note` | Додати нотатку з тегами (через кому) |
| `list-notes` | Усі нотатки |
| `search-notes` | Пошук за текстом або тегом |
| `edit-note` | Редагувати нотатку за ID |
| `delete-note` | Видалити нотатку за ID (з підтвердженням) |
| `search-tag` | Нотатки, що мають **усі** задані теги |
| `notes-by-tag` | Нотатки, згруповані за тегами в алфавітному порядку |

Формати: телефон `+380XXXXXXXXX`, `380XXXXXXXXX` або `0XXXXXXXXX` (пробіли, дужки й дефіси дозволені);
дата `ДД.ММ.РРРР`.

## Де зберігаються дані

За замовчуванням у `~/.personal_assistant/`:

- `contacts.json`, `notes.json` — для сховища JSON (типове);
- `assistant.db` — для сховища SQLite.

Запис у JSON атомарний: обрив під час збереження не псує файл. Якщо файл пошкоджено вручну,
його буде перейменовано на `*.corrupt-<час>.json`, а помічник продовжить роботу з порожнім списком.

| Змінна середовища | Значення |
|---|---|
| `PERSONAL_ASSISTANT_HOME` | Інша папка для даних |
| `PERSONAL_ASSISTANT_STORAGE` | `json` (типово), `sqlite` або `memory` (без збереження) |

```bash
PERSONAL_ASSISTANT_STORAGE=sqlite assistant
```

## Архітектура

Детальний опис із діаграмами пакетів, класів і послідовності викликів —
у [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

```
src/personal_assistant/
  domain/          сутності (Contact, Note), value objects з валідацією, доменні помилки — без I/O
  application/     сервіси (ContactService, NoteService) і порти (ContactRepository, NoteRepository, Clock)
  infrastructure/  реалізації портів; фабрика сховищ (factory.py); системний годинник
    storage/
      json/        JSON-файли з атомарним записом і карантином пошкоджених файлів
      sqlite/      SQLite (stdlib sqlite3): з'єднання і схема, репозиторії контактів і нотаток
      memory/      in-memory, без збереження (також база для JSON)
  presentation/    CLI: цикл команд (cli.py), реєстр, усі тексти українською (messages.py)
    commands/      обробники команд: контакти, нотатки, системні
    io/            покрокові запитання, розбір відповідей, таблиці rich
  main.py          composition root — єдине місце, що збирає всі шари
```

Залежності спрямовані лише всередину: `presentation → application → domain`,
`infrastructure → application (порти) + domain`. Домен не знає ні про файли, ні про консоль.

### Як додати нове сховище (наприклад, PostgreSQL)

1. Створіть пакет `infrastructure/storage/<назва>/` з класами, що реалізують `ContactRepository` і `NoteRepository`
   з `application/ports.py` і кидають лише доменні помилки.
2. Додайте функцію-будівник і запис у `STORAGE_BACKENDS` у `infrastructure/factory.py`.
3. Додайте бекенд у `tests/contract/conftest.py`. Якщо контрактні тести проходять — підміна безпечна.

Домен, сервіси й CLI при цьому не змінюються.
